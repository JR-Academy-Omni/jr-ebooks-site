CHAPTER 01

大厂 AI 岗 JD 反复出现什么

不同公司叫法不一样：AI Engineer、GenAI Engineer、Applied AI Engineer、LLM Engineer、AI Platform Engineer。公开 JD 的共同信号大概分 6 类。

LLM App

把模型接进业务

不是只调 API。要会结构化输出、工具调用、prompt 版本、fallback、错误处理和用户体验。

RAG

让模型查得到、答得准

数据切分、embedding、metadata、rerank、引用、权限、更新策略和失败样例。

Agent

让系统会做事但不乱做

tool schema、planner、memory、权限边界、human-in-the-loop、超时和重试。

Eval

证明系统变好了

离线 eval、在线反馈、golden set、回归测试、trace、成本、延迟和安全指标。

Production

能上线、能排错、能控成本

API、queue、cache、observability、deployment、rate limit、secret、rollback。

Collab

和产品、数据、安全一起干活

AI 岗不是单人炫技。要能解释 trade-off，写文档，和非技术角色对齐风险。

CHAPTER 03

RAG 自查清单

RAG 不是“丢进向量库再问”。公开 JD 里写 retrieval、knowledge base、enterprise data、grounding，本质都在看这一块。

RAG

能勾上这些，才不像教程项目

我能解释 chunk size、overlap、metadata 为什么这么设
不是照默认参数。
我做过 hybrid search 或 rerank 对比
知道什么时候关键词比 embedding 更稳。
我能处理权限和引用
用户看不到的文档，模型也不能拿来回答。
我有失败案例库
至少 20 条：找不到、找错、答偏、引用错、权限错。
我能说清 freshness 和更新策略
文档变了以后，索引怎么更新，缓存怎么失效。

CHAPTER 04

Agent / Tool Use 自查清单

Agent 岗位最怕“能跑但不可控”。面试会追：工具怎么定义、怎么防止乱调用、怎么让人审批、怎么回滚。

Tool Schema

参数清楚，输出可验证

每个 tool 要有明确输入、输出、错误码和权限，不要让模型自由编参数。

Control

能中断、重试、降级

超时、API 失败、工具返回异常时，要有 retry、fallback、human review。

Memory

知道什么该记，什么不该记

用户偏好、任务状态、临时上下文和隐私数据要分开处理。

Audit

每一步都能追溯

谁触发、模型决定了什么、调用了哪个工具、结果是什么，都要 trace。

Agent 项目最小证据

做一个“客服工单 agent”或“内部知识库 action agent”：能检索资料、创建/更新工单、遇到退款/删除/权限动作时要求人工确认，并保留 trace。

CHAPTER 05

Eval / Observability 自查清单

AI 系统和普通系统最大的差别：你不能只测“接口通不通”。你要测回答好不好、有没有引用、有没有胡说、有没有越权。

指标看什么项目里怎么证明
Answer quality答案是否解决用户问题golden set + 人工评分规则
Groundedness答案是否基于资料引用片段和原文对齐检查
Retrieval该找的文档有没有找出来top-k hit rate / recall 样例
Safety是否泄露、越权、被注入prompt injection 和 PII 测试集
Cost / latency每次调用多少钱、多慢trace dashboard 或日志统计
Regression改 prompt 后有没有变差CI 里跑 eval 或手动回归表
项目没有 Eval，面试容易被追卡
扫码找 Amelia，把 RAG/Agent 项目发来，先看该补 golden set、trace 还是失败样例。

Production / Cloud / Safety 自查清单

大厂 AI 岗不会只问 demo。会问如果上线给 10 万用户，怎么控成本、怎么限流、怎么观测、怎么处理坏回答。

生产化

上线前要能回答的问题

我知道每次请求的 token 成本和延迟来源
prompt、retrieval、rerank、tool call 都要能拆。
我有 fallback 和降级策略
模型超时、检索为空、工具失败时怎么回。
我能处理 secret、PII、权限和审计日志
不要把企业数据当 playground。
我能画出部署架构
API、queue、worker、vector DB、object storage、monitoring。
我能解释 guardrail 的边界
不是加一句 system prompt 就完了。

CHAPTER 08

面试高频题

AI Engineer 面试的追问，经常从项目细节开始。下面这些题，别背概念，用你的项目答。

RAG

RAG 答错了怎么排查？

先分 retrieval miss、bad chunk、rerank 问题、prompt 问题、模型幻觉，再看 trace 和样例。

Eval

怎么证明新版 prompt 更好？

用固定 eval set 做回归，比较 groundedness、task success、cost、latency，不只看 3 个手测例子。

Agent

Agent 为什么会乱调用工具？

tool 描述不清、权限边界弱、缺少状态机、没有人审、错误返回不可解释，都可能导致。

Safety

怎么防 prompt injection？

区分系统指令和外部内容，做 allowlist tool、引用隔离、权限检查、输出验证和攻击样例测试。

System

成本突然升高怎么办？

查 token、retrieval、rerank、重复请求、cache hit、模型选择和超长上下文。

Product

什么时候不该用 LLM？

规则稳定、风险高、可解释性强要求、低延迟低成本任务，可能用传统逻辑更好。

再准备这 12 题

chunk 策略、embedding 选择、metadata 权限、hybrid search、rerank、structured output、function calling、streaming UX、rate limit、observability、PII、human-in-the-loop。
