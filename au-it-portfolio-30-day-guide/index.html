先看：作品集不是作业合集

澳洲 IT 早期求职，作品集不是“我做过几个课设”的仓库列表。招聘方真正想看的是：你能不能把一个小问题从需求、实现、部署、测试、文档讲完整。

说白了，一个能打开的项目，比五个只写了“Coming soon”的仓库强。一个写清楚失败和取舍的 README，比一堆技术名词更像干过活的人。

CHAPTER 01

先选目标岗位，不要先选技术栈

很多同学卡在第一步：到底做 React 项目、Python 项目，还是 AI 项目？顺序反了。先选 2 个目标岗位，再反推项目证据。

Frontend

看交互和工程习惯

项目要有路由、表单校验、状态管理、API 调用、loading/error 状态、响应式截图。别只放静态 landing page。

Backend

看 API 和数据建模

项目要有认证、数据库 schema、错误处理、日志、测试、API 文档。README 里画清请求流程。

Data

看数据问题怎么落地

项目要有数据来源、清洗、指标定义、可视化、结论和限制。别只贴一张 dashboard。

Cyber / Cloud

看安全边界和部署

项目要有 threat model、权限、监控、IaC、CI/CD 或云部署截图。别写“熟悉 AWS”就完了。

做作品集前，先去 Jobs and Skills Australia、SEEK、LinkedIn 找 10 条目标 JD，把共同要求抄出来。项目不是为了炫技，是为了回答 JD。

CHAPTER 02

作品集的 6 个必备证据

“我做了一个项目”不够。你要让没见过你的人，三分钟内看懂项目能跑、你做了关键部分、你知道哪里难。

证据要放什么常见坑
GitHub干净 repo、清晰 commit、可运行说明只有 zip 解压代码
README背景、功能、架构、安装、截图、测试只写技术栈列表
Demo线上链接或 60 秒录屏面试官点不开
截图核心页面、错误状态、后台或 dashboard只放首页
测试单测、API 测试、数据校验或安全检查完全没有验证
讲法STAR、技术决策、trade-off、下一步只会说“我负责开发”

一句话自检

如果 recruiter 只看你的 README 和截图，不跑代码，也能知道你解决了什么问题、用了什么技术、哪里体现岗位能力，这个作品集才算能递出去。

CHAPTER 03

30 天执行表

别等“学完再做”。30 天只做一件事：把一个中等大小项目做到能展示。每天任务不要超过 90 分钟，不然很容易断。

阶段天数交付物具体动作
定岗位1-3目标 JD 表找 10 条岗位，圈出共同技能、业务场景、动词。选一个主岗位、一个备选岗位。
定项目4-6项目 brief写清用户是谁、痛点是什么、MVP 做哪 5 个功能、不做什么。
搭骨架7-10可运行 repo初始化项目、建数据库或 mock data、写 README 草稿、开 issues。
核心功能11-17能跑的 MVP每天只推进一个功能。做完就截图，不要等最后补。
质量证据18-21测试和错误处理补 API 测试、数据校验、loading/error、安全或权限说明。
包装22-26README + Demo录 60 秒 demo，补架构图、技术取舍、已知限制和下一步。
投递材料27-30简历 bullet + 面试讲法把项目改成 3 条简历 bullet，准备 2 分钟英文讲法和 5 个追问答案。

按岗位选项目

项目不用大，但要像岗位。下面这些选题都能做成小而完整的作品集。

Frontend

Rental Inspection App

租房检查清单、照片上传、缺陷分类、PDF 报告。重点展示表单、状态、移动端和可用性。

Backend

Clinic Booking API

预约、医生排班、用户权限、冲突检测、API 文档。重点展示 schema、错误处理和测试。

Data Analyst

Job Market Dashboard

抓取公开岗位样本，按技能、城市、岗位类型做 dashboard。重点展示指标定义和洞察。

Data Engineer

ETL Quality Pipeline

从 CSV/API 到 warehouse，加入数据质量检查、日志和重跑策略。重点展示 pipeline 可靠性。

Cyber

Access Review Tool

导入用户权限，识别异常角色和过期账号。重点展示 threat model、audit log 和 least privilege。

AI Engineer

Course Advisor RAG

基于课程 handbook 的问答助手。重点展示检索、引用、eval、失败案例和安全边界。

CHAPTER 05

项目 README 模板

README 不是说明书尾巴，它就是你的作品集首页。招聘方先看它，再决定要不要继续点。

可直接复制的 README 结构

  • Project name：一句话说明项目解决什么问题。
  • Context：谁会用，为什么需要它。
  • Features：列 5 个核心功能，不要列 20 个。
  • Tech stack：每个技术写“为什么用”，别只堆名字。
  • Architecture：一张图或文字流程，说明前端、后端、数据库、第三方服务。
  • How to run：安装、环境变量、启动命令、测试命令。
  • Screenshots / Demo：至少 4 张截图或 60 秒录屏。
  • Testing / Validation：你怎么确认它没坏。
  • Trade-offs：时间不够时你砍掉了什么，为什么。
  • Next steps：下一版会补什么，和目标岗位能力有什么关系。
别写“使用先进技术栈”。直接写：用了 PostgreSQL，因为预约冲突需要事务；用了 Redis，因为搜索结果可以缓存 10 分钟。

CHAPTER 06

简历 bullet 怎么写

作品集做完，还要翻译成简历语言。别写“负责项目开发”。要写动作、技术、结果和验证方式。

弱写法改成这样
Developed a web app using React.Built a React inspection workflow with form validation, image upload and mobile responsive views, reducing manual report steps from 6 screens to 2.
Used Python for data analysis.Created a Python pipeline to clean 12 months of job-posting samples, classify skills and publish a dashboard for weekly trend review.
Implemented backend APIs.Designed REST APIs for booking, cancellation and schedule conflict checks with PostgreSQL constraints and integration tests.
Made an AI chatbot.Built a RAG course advisor with chunk metadata, citation display and 20-case eval set to catch unsupported answers.

CHAPTER 07

面试怎么讲项目

面试官问项目，不是让你背 README。他想听你怎么做决定，怎么处理限制，怎么知道方案有效。

开场

30 秒讲清背景

“这个项目模拟 rental inspection 场景，用户是 property manager。痛点是现场记录分散，最后报告要手工整理。”

技术

讲一个关键决策

“图片上传没有直接塞进数据库，而是存对象存储，数据库只保存 URL 和 metadata，因为后面要做报告导出。”

问题

主动讲一次失败

“第一版表单状态太分散，后来改成 step state，错误提示统一处理，测试也更容易写。”

结果

落回岗位能力

“这个项目主要证明我能把需求拆成工作流、写可维护组件、处理 API 错误和移动端体验。”

5 个一定要准备的追问

为什么选这个技术？如果用户量变大怎么办？你怎么测试？安全和隐私怎么处理？如果再给两周你会改什么？

发布前检查清单

作品集发布前，用这页扫一遍。能勾上的越多，越像求职材料；勾不上，就先别急着投。

GitHub

仓库能不能给陌生人看

README 第一屏说清项目价值
别让人先滚 3 屏才知道你做了什么。
有启动命令、环境变量和测试命令
哪怕别人不跑，也能看出你认真交付。
没有密钥、个人隐私、学校未授权材料
`.env`、真实用户数据、公司资料都不要放。
Portfolio

页面能不能帮你争取面试

每个项目都有截图或录屏
面试官没时间先装依赖。
每个项目都对应一个目标岗位能力
不是“我做过很多”，而是“我能做这份工作”。
简历 bullet 和 README 说的是同一件事
别简历写 AI，README 打开是 Todo App。
