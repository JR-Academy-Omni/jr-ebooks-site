CHAPTER 01

澳洲 / 中国 JD 有什么不同

澳洲和中国都要全栈，但招聘语言不一样。澳洲 JD 更常把沟通、ownership、cloud、CI/CD、testing 写进要求；中国 JD 更常把业务迭代速度、Vue/React、Java/Spring Boot、微服务、小程序、性能优化写得很细。

Australia

看完整交付

SEEK 当前 full stack 搜索里能看到 React、Node、TypeScript、AWS、Java、Angular 等组合。简历要证明你会做功能、测试、部署和沟通。

China

看栈匹配和上线速度

常见信号是 Vue/React、Java/Spring Boot、Node、MySQL/Redis、微服务、权限、性能、小程序。简历要写清模块、接口、并发和上线结果。

共同点

都不喜欢“只会教程”

如果项目没有登录、CRUD、错误处理、数据库关系、部署和 README，招聘方很难判断你能不能进团队。

差异点

澳洲更吃表达，中国更吃细节

澳洲面试常追项目决策和协作；中国面试更容易追框架原理、接口设计、SQL、缓存、并发和八股基础。

先别问哪个国家更容易。先把目标 JD 贴出来，圈出重复出现 5 次以上的关键词，那才是你第一阶段要学的东西。

CHAPTER 02

技术栈路线图：按顺序学

路线不是越长越好。转码第一阶段只要一条主线：TypeScript + 一个前端框架 + 一个后端框架 + SQL + Git/Docker + 基础云部署。

顺序先学什么要做到什么程度别一开始做什么
1HTML / CSS / JavaScript / TypeScript能写表单、校验、异步请求、模块化代码背一堆冷门语法
2React 或 Vue 二选一路由、状态、组件拆分、loading/error、表单两个框架同时学
3Node/Express/Nest 或 Java/Spring BootREST API、认证、错误处理、日志、测试只跟视频抄 CRUD
4SQL + Redis 基础表关系、索引、事务、缓存失效上来就学复杂分库分表
5Git / Docker / CI能用分支、PR、容器化、本地一键启动只会 zip 代码
6AWS / Azure / Vercel / Render能部署前后端、配置环境变量、看日志考证代替项目
澳洲优先

React + TypeScript + Node/AWS

适合投 full stack / frontend-heavy 岗。项目要有测试、部署、英文 README 和 business context。

中国优先

Vue/React + Java Spring Boot

适合投中大型互联网、企业软件和外包/项目制公司。要补 SQL、Redis、接口、权限、性能和基础八股。

8 周学习和项目计划

别做“无限学习计划”。8 周只交付一个可投递项目和一份能讲清楚的简历。

周主题产出验收标准
1JS/TS + Git小型数据表单能提交 PR，能解释 async/await、类型、模块。
2React 或 Vue前端页面 4 个有路由、表单校验、API mock、错误状态。
3后端 APIREST API + auth能解释 token、middleware、status code。
4数据库schema + 查询能画 ERD，解释索引和事务。
5整合前后端联调登录、CRUD、权限、错误处理都能跑。
6测试和质量单测/API 测试至少覆盖核心 service 和 3 条失败路径。
7部署线上 demo环境变量、日志、README 启动命令齐全。
8简历和面试3 条 bullet + 20 个问答能 2 分钟讲项目，能答技术取舍。

真实 JD 拆解：关键词怎么翻译

JD 不是愿望清单。你要把每条要求翻译成“简历证据”和“面试故事”。

JD 写法它真正想看你怎么证明
React/Vue, reusable components组件拆分、状态管理、可维护性README 放组件结构图，简历写一个复杂表单或 dashboard。
Node/Spring Boot REST APIs接口设计、错误处理、认证、日志放 API 文档和测试截图，面试讲 status code 和 auth flow。
SQL, database designschema、索引、事务、查询性能放 ERD，讲一次慢查询或数据一致性处理。
AWS/Docker/CI/CD能部署、能排错、知道环境差异放部署架构和日志截图，讲一次 production-like bug。
Agile, stakeholder communication能在团队里交付，不是自己玩写 issue、PR、验收标准，准备一个需求变更故事。

项目组合：别只做 Todo App

全栈项目要像真实业务。一个项目就够，但必须有用户、权限、数据、错误和部署。

用户端下单或预约，后台审核和数据统计。适合展示业务闭环、接口、权限和上线速度。

CHAPTER 06

简历模板：把技术写成证据

全栈简历最怕写成技能清单。招聘方不缺“会 React 的人”，缺的是能把功能做完的人。

项目 bullet 模板

  • Built [feature] using [stack] to solve [user problem], covering [frontend + backend + database evidence].
  • Designed [API/schema/auth flow] with [validation/testing/logging], reducing [manual step / error / repeated work] in the demo workflow.
  • Deployed the app with [Docker/cloud/CI], documented setup in README, and handled [failure case] through [specific fix].
弱写法改成这样
熟悉 React、Node、MySQL。Built a role-based maintenance portal with React, Node.js and MySQL, including ticket workflow, image upload and admin status tracking.
做过 Spring Boot 项目。Designed Spring Boot REST APIs for approval workflow with JWT auth, MySQL schema, Redis caching and integration tests for failed submissions.
了解 AWS 部署。Containerised the backend with Docker and deployed a live demo with environment variables, logs and rollback notes documented in README.

CHAPTER 07

面试高频题：怎么答才像干过活

题目不是拿来背的。每道题都要落回你的项目，不然听起来像搜索答案。

Frontend

React/Vue 状态怎么设计？

答：先区分 server state、form state、UI state。举项目里搜索、分页、表单错误怎么处理。

Backend

登录认证怎么做？

答：讲 password hash、JWT/session、middleware、权限检查、token 过期和错误返回。

Database

为什么要加索引？

答：讲查询条件、排序、写入成本。最好用你项目里的 ticket status 或 user_id 查询举例。

System

如果用户量变大怎么办？

答：先定位瓶颈，再讲缓存、分页、异步任务、数据库连接池、日志和监控。别一上来就微服务。

Cloud

线上挂了怎么排查？

答：看 health check、logs、env vars、database connection、recent deploy、rollback。讲一个你项目里的排错例子。

Behavioral

需求变了怎么办？

答：用 STAR。说清 trade-off、沟通、拆 scope 和保住核心交付，不要只说“我加班完成”。

再准备这 12 题

事件循环、Promise、组件复用、表单校验、REST vs GraphQL、HTTP 状态码、SQL join、事务、缓存穿透、Docker 镜像、CI/CD、项目里最难的 bug。
