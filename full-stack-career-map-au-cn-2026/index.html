先看：全栈不是把所有东西都学一遍

转码最容易掉进一个坑：今天学 React，明天学 Vue，后天学 Java，周末又去补 AWS。学了很多，但 JD 一打开，还是不知道自己能投什么。

全栈求职不是“前后端数据库云都精通”。早期岗位更看重：你能不能做一个完整业务功能，从页面、API、数据库、权限、部署到排错都说得清楚。

先说一句实话，别学到一半才发现市场在降温。2025 年，澳洲 Jobs and Skills Australia 第一次把 Software Engineer 移出了全国短缺清单；中国这边，斯坦福一份研究显示 2022 年底到 2025 年 7 月，22–25 岁的年轻程序员就业人数掉了近两成。这不是叫你别学，是叫你别用三年前的乐观预期来学 —— 门槛更高了，你的项目和简历得更能打。

CHAPTER 01

澳洲 vs 中国：面试流程、时间线、卡点全对比

这是这本书唯一别人抄不走的部分。两地都要全栈，但招人的方式差得很远。你要是拿中国那套准备去投澳洲，或者反过来，基本会撞墙。下面一条条拆。

一、面试流程和轮次

环节澳洲（真实 4 轮为主）中国（3 轮技术面 + HR）
第一关Recruiter/phone screen，约 30 分钟，聊背景、动机，还有一句几乎必问：你有没有工作签证。一面，直接上技术。项目 + 基础八股 + 可能现场手撕一道算法。
技术关take-home 项目 / timed coding / system design，三选一或组合。有的会让你 review 一段 PR。二面，项目拷打为主：这个模块你怎么设计的、并发多大、怎么优化的、踩过什么坑。
软性关pair programming + 和 lead engineer 聊，夹着 culture fit 和情景行为题，权重和技术一样高。三面，经理面，看综合能力和稳定性，有的大厂到这轮才谈别的。
收尾final + reference check，会真的打电话给你前同事核实。HR 面，谈薪资、到岗时间、家庭情况，部分大厂三面后就没有独立 HR 面。
一个真实例子：悉尼/珀斯的 Sitemate，候选人报告的流程是 —— 先做一个对接第三方 API 的 take-home，再 pair programming + 技术面，再情景文化面，最后 reference check。注意它把“review 一段 PR、描述你会怎么实现某功能”当技术题，不是纯刷 LeetCode。（来源：Glassdoor，2026-07 查）

二、时间线：什么时候投

Australia

全年滚动，没有招聘季

澳洲大部分岗位常年在招，看到合适的就投，不用等。唯一例外是大厂和银行的 graduate program，有固定年度批次，通常提前大半年开。

China

秋招是主战场，卡毕业月份

秋招 9–11 月放最多 headcount，春招 3–4 月补录，社招常年。应届生身份和毕业时间强绑定，错过窗口很吃亏。2026 秋招一般收 2026.1–2027.8 毕业的同学。

三、卡点：真正卡住人的地方不一样

澳洲卡在哪中国卡在哪
硬门槛工作身份。大量岗（尤其远程岗、政府/公共机构）写死要 current Australian work rights，纯海外身份直接被 screen 掉。学历和第一学历。大厂校招约 1:50，头部国企常看是不是 985/211；非名校要靠竞赛、项目或稀缺技能突围。
隐性门槛愿不愿 sponsor 签证，更多看公司规模和它是不是已经是 approved sponsor，而不是岗位本身。startup 薪资开得高但担保逐案而定。年龄。筛简历第一眼看年龄，25–28 岁优先约面，35 岁以上除非有稀缺技能，简历常直接进待定区。
身份的坑PR 让你从“需要担保”变“随便投”，但拿 PR 是另一条长路，别把学技术和拿身份混成一件事。留学生应届身份：回国 2 年内别急着签正式劳动合同、别缴国内职工社保 —— 一旦职工社保记录出现，多数企业和考公岗会认定你不再是应届生。

四、phone screen / 一面真会问什么

澳洲一面示例

先讲一个完整项目

“介绍一个你从前端、后端到部署完整做过的项目” —— 这是最常见的开场。接着可能让你 review 一段 PR 指出问题，或者口述你会怎么实现某个功能。再夹一道行为题：跨团队协作、冲突怎么解决。澳洲对表达和 culture fit 的权重，和技术是并列的。

中国一面示例

项目深挖 + 八股

顺着你简历里的项目往死里问：模块怎么设计、数据量多大、慢查询怎么优化。然后是 Java 核心（JVM、多线程、Spring Bean 生命周期）、MySQL 索引、Redis 缓存穿透击穿雪崩，可能现场一道算法。考察优先级：项目深挖排第一，八股排第二。

一句话记住差别澳洲那关，你得能把项目讲成一个“我怎么和人协作交付”的故事；中国那关，你得能把项目讲到“并发、索引、缓存”这种细节，还能扛住追问。同一个项目，两地要练两套讲法。

岗位数量和市场温度

别只看“缺人”的老新闻澳洲：SEEK 当日全澳挂 555 个全栈岗，量还在，但 2025 年 Software Engineer 和 Developer Programmer 双双被移出 JSA 全国短缺清单 —— 2021 年开始统计以来第一次。中国：2025 大厂校招回暖（京东 2026 校招 3.5 万岗），但斯坦福研究显示 2022 年底到 2025 年 7 月，22–25 岁年轻程序员就业累计减少近 20%。结论就一句：岗位有，但入门更卷了，靠项目和简历拉开差距。

签证 / PR：澳洲这条一定要看懂

很多人一看到“Software Engineer 掉出短缺清单”就慌，其实误读了。掉出短缺清单，不等于不能移民。

Developer Programmer（261312）和 Software Engineer（261313）仍然在 MLTSSL 和 CSOL 上，签证通道还开着：189（技术独立 PR）、190（州担保 PR）、491（偏远地区 PR 跳板）、482 Skills in Demand（雇主担保，最长 4 年，PR 跳板）、186（雇主提名 PR）。技术评估走 ACS。

真正卡你的不是清单，是工作身份：很多岗写死要 current Australian work rights，纯海外身份会被 screen 掉。谁愿意 sponsor，更多看公司规模和它是不是已经是 approved sponsor，不是看岗位。

留学生应届身份（回国方向）留学回国不分应届往届、没有三方协议，“是否应届由用人单位界定”，离校 2 年内没落实工作可按应届参加招聘。红线：回国 2 年内别急着签正式劳动合同、别缴国内职工社保，一旦职工社保记录出现，多数企业和考公岗就认定你不再应届。互联网大厂通常要毕业 1 年内可投，金融类友好些，接受 2–3 年内。

读到这一章，如果你在纠结“我这个身份/背景到底投澳洲还是回国划算”，这不是一句话能定的。扫 Rain 的码，把你的签证状态、毕业时间和目标城市发来，先帮你把路线捋一版。不承诺签证、offer 或收入结果。

CHAPTER 04

技术栈路线图：按顺序学

路线不是越长越好。转码第一阶段只要一条主线：TypeScript + 一个前端框架 + 一个后端框架 + SQL + Git/Docker + 基础云部署。

顺序先学什么要做到什么程度别一开始做什么
1HTML / CSS / JavaScript / TypeScript能写表单、校验、异步请求、模块化代码背一堆冷门语法
2React 或 Vue 二选一路由、状态、组件拆分、loading/error、表单两个框架同时学
3Node/Express/Nest 或 Java/Spring BootREST API、认证、错误处理、日志、测试只跟视频抄 CRUD
4SQL + Redis 基础表关系、索引、事务、缓存失效上来就学复杂分库分表
5Git / Docker / CI能用分支、PR、容器化、本地一键启动只会 zip 代码
6AWS / Azure / Vercel / Render能部署前后端、配置环境变量、看日志考证代替项目

规格二 · 企业审批系统（中国向，Vue + Spring Boot + MySQL + Redis）

用户故事

  • 作为员工，我能提交请假/报销申请，看到它走到哪一步、被谁审批。
  • 作为直属主管，我审批我下属的申请，能同意/驳回并写理由。
  • 作为财务，报销在主管通过后流转到我这里做二次审批。
  • 作为管理员，我配置审批流（几级审批、谁审）、管理部门和角色。

数据库 schema（MySQL）

sys_user     (id, username, password, dept_id, role_id)

sys_role     (id, name, code)               -- employee/manager/finance/admin
approval_flow(id, type[leave|expense], steps_json)  -- 审批流配置
apply        (id, applicant_id, type, amount, reason, status,
              current_step, created_at)      -- 一张申请单
apply_record (id, apply_id, approver_id, action[pass|reject],
              comment, step_no, created_at)  -- 每一步审批留痕
索引：apply(applicant_id, status)、apply(current_step)、apply_record(apply_id)

Redis 用在哪：登录 token、审批流配置缓存、待办数量计数（避免每次 count 查库）。

验收标准① 审批流可配置成一级或两级，报销走两级、请假走一级；② 同一步不能重复审批，审批后状态和 current_step 正确流转；③ 待办数量从 Redis 读，申请状态变化时更新计数；④ 越权审批（审别人下属）返回无权限；⑤ 每一步写 apply_record，详情页能看到完整审批链路；⑥ 压一下并发提交，说得清幂等怎么处理。

CHAPTER 09

面试高频题：8 道完整范例答案

题目不是拿来背的。下面 8 道，每道给一版“像干过活”的答法，再给一版“一听就是背的”反面对照。都落回第 06 章那两个项目讲。

FrontendReact/Vue 的状态该怎么设计？

✅ 像干过活的答法我会先把状态分三类：server state（后端数据，比如维修单列表）、form state（正在填的表单）、UI state（弹窗开没开、loading）。server state 我用 React Query 管缓存和刷新，不塞进全局 store，避免数据不一致。举我项目里的例子：维修单列表有筛选和分页，筛选条件是 URL state，列表数据是 server state，提交表单的错误是局部 state，三者分开，改一个不影响另一个。
🚫 一听就是背的“状态管理就用 Redux，把所有数据放进 store 统一管理。” —— 全塞全局是新手信号，面试官会追问“列表数据也放 Redux 吗，那刷新怎么办”，然后你就卡住了。

Backend登录鉴权你怎么做？

✅ 像干过活的答法密码用 bcrypt 加盐存，不存明文。登录成功签一个 JWT，放 access token（短期）+ refresh token（长期）。每个受保护接口过一个 middleware 校验 token 和角色。我项目里三种角色权限不同，middleware 里先验 token 再查这个角色能不能调这个接口，越权返回 403。token 过期返回 401，前端拿 refresh token 换新的。
🚫 一听就是背的“用 JWT 做登录，把用户信息存在 token 里。” —— 太浅，而且往 token 里塞敏感信息是坑。面试官会问“token 怎么失效、密码怎么存、越权怎么拦”，答不上就露馅。

Database为什么要加索引？一条慢查询怎么优化？

✅ 像干过活的答法索引是拿写入变慢和存储换查询变快。加在高频查询条件和排序字段上。我项目里维修单按 status 和 assigned_to 查最多，就在 (assigned_to, status) 上建联合索引。真遇到慢查询我会先 EXPLAIN，看是不是全表扫、有没有走索引，再决定加索引还是改查询。不是无脑加，因为写多读少的表加太多索引反而拖慢。
🚫 一听就是背的“加索引能加快查询速度，所以把常用字段都加上索引。” —— 每个字段都加是反效果。面试官一句“那写入变慢怎么办、联合索引最左匹配懂吗”就问穿了。

System用户量变大了怎么扩容？

✅ 像干过活的答法先别急着上架构。我会先定位瓶颈：看监控和日志，是数据库慢、还是某个接口慢、还是没加缓存。按性价比从低到高来：先加索引和分页，再加 Redis 缓存热点数据，再把耗时操作（发邮件、生成报表）改成异步队列，再考虑读写分离。数据库连接池、慢查询这些先榨干，微服务和分库分表是最后才碰的。
🚫 一听就是背的“用户量大就上微服务、分库分表、加机器。” —— 一上来就重架构，面试官知道你没真扛过量。真实场景里 90% 的问题加个索引或缓存就解决了。

Ops线上挂了，你怎么排查？

✅ 像干过活的答法有套路的：先看是不是刚部署过（最常见，先想能不能 rollback 止血）。再按链路查：health check 过不过、日志有没有报错、环境变量对不对、数据库连得上吗、第三方服务挂没挂。我项目里踩过一次，本地好好的线上 500，最后是环境变量少配了数据库密码，看日志三分钟定位。排查顺序永远是先止血、再定位、再修。
🚫 一听就是背的“看一下报错，然后改代码重新部署。” —— 没有章法。面试官想听的是你有没有一套“止血→定位→复盘”的流程，而不是撞运气。

China 高频Redis 缓存穿透、击穿、雪崩怎么处理？

✅ 像干过活的答法三个是不同问题。穿透：查一个根本不存在的 key，每次都打到库，用布隆过滤器或缓存空值挡。击穿：某个热点 key 突然过期，大量请求同时打库，用互斥锁让一个请求去回源、其他等着。雪崩：大批 key 同一时间过期，给过期时间加随机偏移错开。我审批系统里待办数量是热点，就缓存计数并给过期时间加随机值。
🚫 一听就是背的把三个概念背一遍但分不清区别，或者只会说“加缓存”。面试官会给个具体场景让你选方案，分不清就答错。

Behavioral做到一半需求变了，你怎么办？

✅ 像干过活的答法用 STAR。情境：项目做到第 5 周，PM 说审批要从一级改成两级。我做的：先评估影响，发现 schema 和流转逻辑要改；跟 PM 确认核心是先保证能跑通两级，UI 优化可以放后面；把变更拆成“先加一步审批、再补配置界面”两步。结果：核心功能按时交付，配置界面下个迭代补上。重点是我说清了取舍和沟通，不是“我加班硬做完”。
🚫 一听就是背的“需求变了我就加班加点把它做完。” —— 澳洲面试尤其不吃这套。他们想看你会不会评估影响、砍 scope、和 stakeholder 沟通，而不是无脑扛。

Project讲一个你项目里最难的 bug？

✅ 像干过活的答法挑一个有“定位过程”的。比如：维修单偶尔状态回退，复现不了。我加日志发现是前端两个请求并发，后到的旧数据覆盖了新状态。解决：后端加乐观锁（版本号），前端禁掉重复提交。讲清楚“现象→怎么定位→根因→怎么修→怎么防复发”，这一条就够撑一轮技术面。
🚫 一听就是背的“最难的 bug 是一个报错，我 Google 了一下就解决了。” —— 等于没答。面试官问这题就是想看你的 debug 思路和技术深度，随便糊弄会直接减分。
